СЛОВАРЬ РАБОЧЕГО ДНЯ

Junior

Начинающий разработчик. Он уже умеет писать код, но ещё набирается опыта и часто работает с поддержкой наставника.

Bug / баг

Ошибка в программе: она работает не так, как ожидалось.

Git

Система контроля версий. Помогает сохранять историю изменений и возвращаться к предыдущему состоянию кода.

Branch / ветка

Отдельная линия разработки. В ней можно работать над задачей, не затрагивая основную версию проекта.

Commit

Зафиксированный набор изменений с коротким описанием того, что было сделано.

Code review

Проверка кода другим разработчиком. Это способ улучшить решение и заметить проблемы до релиза.

Test / тест

Проверка поведения программы в конкретных условиях: обычных, граничных и ошибочных.

Deploy / релиз

Публикация новой версии приложения, чтобы изменения стали доступны пользователям.

Backend

Серверная часть приложения: правила, обработка данных, проверка прав и взаимодействие с базой данных.

AFTER THE SIMULATION

Что важно запомнить

Разработчик не просто превращает задачу в код. Он уточняет требования, изучает существующий проект, делит работу на безопасные шаги, проверяет гипотезы, тестирует и объясняет команде свои решения. Ошибаться можно — гораздо важнее уметь находить причину и исправлять её.
